# warewoolf / NEO / Fountain 系调研：纯写作的交互原语与领域 DSL

> 调研日期：2026-08-31
> - warewoolf：https://github.com/brsloan/warewoolf ｜ 338★ ｜ JS（Electron + 硬件 writerDeck）｜ 活跃
> - NEO：https://github.com/hughhowey/neo ｜ 289★ ｜ JS ｜ 活跃（小说家本人开发）
> - BetterFountain：https://github.com/piersdeseilligny/betterfountain ｜ 448★ ｜ VS Code 扩展 ｜ 活跃
> 定位：三个"反大而全"的纯写作项目。它们的功能克制恰好定义了**写作编辑器必须做对的原语层**——这层是我们任何插件都夺不走的内核职责。
> 许可证：三者均为 **MIT**（warewoolf/NEO/BetterFountain 已核实），交互实现细节可直接参考代码。

## 1. 为什么看"小"项目

我们的方向是大而全插件化，最大的风险是把"写作"本身做砸——所有花活都建立在"打字舒服"之上。这三个项目是当下最活跃的"纯写作"实验田，贡献了一批值得直接吸收的交互原语。

## 2. warewoolf：无鼠标写作的极端约束

- **三面板、零图标**：Chapters / Editor / Notes 三个文本面板，没有工具栏，连文件菜单都要按 Alt 召唤。所有操作快捷键化，Ctrl+H 显示快捷键表。
- **Reference 区**：章节列表里的特殊分区，存放"不参与编译、不计字数"的文档（人物表、地点表）。——novelWriter Archive 概念的轻量版：**"哪些内容算正文"必须是显式分区，而不是隐式约定**。
- **章节重排自动重编号**：拖动章节顺序后，标题里的 "Chapter One/Two/…" 自动重写。网文场景等价物：章节序号、卷序号联动。
- **MarkdownFic**：面向小说的简化 Markdown 方言（自定义斜体/标题标记、章节分隔符识别），配合纯文本/docx 导入转换。——**小说的"最小标记语言"是可行的中间态**：比 Markdown 语义化（有"场景分隔""对话"概念），比 Fountain 宽松。
- **writerDeck 支持**：内置文件管理器、WiFi 管理、电量监控，跑在专用打字机上。启示：**核心功能不依赖网络/账号/系统服务**，这是"本地优先"的极限测试。
- 一键把草稿发邮件给自己——低技术含量的"云备份"，但对目标用户极其有效。

## 3. NEO：小说家亲手设计的写作流

作者本人是小说家，交互设计密度极高，逐条都是可直接实现的功能点：

- **Enter, Enter, Enter**：一次回车 = 新段落；两次 = `***` 场景分隔；三次 = 新章节。**把结构操作压进连续击键里，不打断心流**——这是写作编辑器最该有而几乎所有通用编辑器都没有的原语。
- **Placeholders（占位符）**：写作中途需要人名/日期/事实时，⌘⇧X 打个标记+便签，继续写。左侧章节列表出现红点，右侧面板汇总所有待填项。**"先占位后补全"是创作工具的核心工作流**，我们的 inspiration/knowledge 应该提供"就地占位"而不是"跳出去查"。
- **Darlings（弃稿回收）**：把舍不得删的段落拖进 Darlings 标签，正文移除但保留**原始位置锚点**，可精确放回。比回收站语义高级：处理的是"暂时移出正文"。
- **Ghost outline（幽灵大纲）**：大纲标签里写的场景备注，以灰色半透明段落**直接显示在正文流中**，写作时覆盖掉即可。大纲和正文不再是两个界面——**规划态和写作态叠加在同一文档流里**。
- **排印自动化**：em dash、弯引号、真省略号边打边修；首字下沉标记章节开头；**拼写检查只在主动调用时出现**（"红波浪线诱发冒名顶替综合征"）。
- **书架隐喻**：图书馆是书架+封面+进度条，不是文件列表。按系列/状态/笔名组织。——UI 隐喻可以很大胆，因为数据层（本地纯文本文件）不受影响。

## 4. Fountain / BetterFountain：领域 DSL + 工具即插件

- **Fountain** 是剧本的纯文本标记语言规范（零配置、任何文本编辑器可写）。核心设计（规范实测提取）：
  - **黄金法则**："make it look like a screenplay"——语法靠视觉惯例而非符号堆砌；**空行是唯一的块分隔符**，解析器"不会越过空行去找闭合标记"，因此没有嵌套歧义、没有转义地狱。
  - **自动识别 + 强制前缀双轨**：场景标题（`INT./EXT` 开头）、角色行（整行大写+前有空行）、转场（大写+`TO:` 结尾）靠启发式识别；识别不了或误判时用行首强制符：`.` 强制场景、`@` 强制角色（保留混合大小写）、`>` 强制转场、`!` 强制动作行。**启发式覆盖 95% 日常输入，强制符兜底 100% 语义**——这是 DSL 设计的关键平衡。
  - 标题页 = 文档开头 `key: value` 块（多值缩进）；`/* boneyard */` 跨块注释（弃稿区，对应 NEO 的 Darlings）。
  - 场景可挂 `#1A#` 编号——为交叉引用/大纲映射预留锚点。
- **BetterFountain 本体是 VS Code 扩展**——剧本写作工具 = 大平台的插件。它因此白嫖了 VS Code 的实时协作（Live Share）、Git、生态。README 原话："BetterFountain 是唯一能实时协作的免费开源剧本工具"，靠的就是宿主平台。
- 哲学："消除脑子和成稿之间的摩擦：没有分页符、没有菜单、回车零延迟"。

**对我们的双重启示**：
1. **数据格式层**：ai-novel 的章节/卡片应能导出为一种"小说版 Fountain"式开放文本 DSL（结合 novelWriter @tag + MarkdownFic），使我们的库可被外部编辑器/AI 工具直接读写——这是比 API 更彻底的开放性。
2. **产品形态层**：除了做独立应用，**同时做一个 VS Code/Obsidian 插件形态**成本极低、获客极好（写作者已在那些工具里），且验证我们的核心库是否真的平台无关。

## 5. 汇总到 ai-novel 的行动项

1. 写作编辑器原语清单（进 09 篇编辑器选型需求）：Enter×3 结构流、占位符+红点、Darlings、幽灵大纲、排印自动修正、按需拼写检查。
2. 章节列表增加显式 "Reference/非正文" 分区，字数统计与编译范围以它为准。
3. 定义 **ai-novel 开放文本 DSL**（小说版 Fountain）：正文 + @tag 引用 + 卡片 frontmatter，作为导入导出与外部工具互操作格式。
4. 规划"宿主插件形态"支线：核心引擎（数据模型+DSL+索引）独立成 npm 包，VS Code 扩展作为第一个宿主试验。
5. 本地优先红线：任何功能不得引入账号/网络依赖（AI 功能除外，但必须可整体禁用——呼应 Twine"扩展非必需"原则）。
